# Лабораторная работа №1. 



## Задание



Написать программу на языке C++ для перемножения двух квадратных матриц.



\- \*\*Входные данные\*\*: файлы `A.txt` и `B.txt` со значениями исходных матриц.

\- \*\*Выходные данные\*\*: файл `C.txt` со значениями результирующей матрицы, время выполнения, объём задачи.

\- \*\*Верификация\*\*: обязательна автоматизированная проверка результатов с помощью сторонних библиотек (NumPy).



## Реализация



Программа состоит из трёх частей:



1\. \*\*`gen.py`\*\* — генератор исходных матриц `A.txt` и `B.txt` заданного размера.

2\. \*\*`main.cpp`\*\* — основная программа: читает матрицы из файлов, перемножает их вложенными циклами, записывает результат в `C.txt`.

3\. \*\*`verify.py`\*\* — верификация результата с помощью NumPy: заново перемножает A и B и сравнивает с `C.txt`.



### Алгоритм умножения



Используется классический тройной цикл без библиотек:



for (int i = 0; i < n; i++)

&#x20;   for (int j = 0; j < n; j++)

&#x20;       for (int k = 0; k < n; k++)

&#x20;           res\[i]\[j] += mat1\[i]\[k] \* mat2\[k]\[j];



Объём задачи: `2·n³` операций (n умножений и n сложений на каждый из n² элементов результата).

## Верификация



Результат проверяется скриптом `verify.py`, который с помощью NumPy заново перемножает матрицы и сравнивает с результатом программы.



Пример вывода:

Size: 200x200
Operations: 16000000
Time: 0.030812 sec
GFLOPS: 0.519278
Verification:
Relative difference: 1.089e-15
Verification passed
## Выводы

1. Время выполнения растёт примерно как O(n³): при увеличении размера матрицы в 2 раза время растёт примерно в 8 раз (для n=200→400 получено ×9.82, для 400→800 — ×9.11, что близко к теоретическому значению).

2. Производительность (GFLOPS) падает с ростом n: с 0.583 при n=200 до 0.180 при n=2000. Это связано с эффектами кэш-памяти: при малых размерах матрицы помещаются в кэш процессора, при больших — постоянно читаются из оперативной памяти.

3. Реализация умножения вложенными циклами корректно работает на всех размерах и подтверждена верификацией через NumPy с погрешностью ~10⁻¹⁵.
